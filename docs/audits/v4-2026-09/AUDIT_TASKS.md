# v4 Delta Audit — Remediation plan (`AUDIT_TASKS.md`)

> Emitted by Phase 5. **Report-only until approved.** Ten one-session batches, keystone first / enforcement last;
> every task states its finding(s), rule, done-when, verify command, the tests that must exist first (TDD), and
> whether it touches core. Order: **B1** keystone gates that other gates depend on → **B2** forge trust boundary
> (Critical-class security) → **B3** tenancy/erasure completeness → **B4** auth/session → **B5** jobs/email/webhooks/
> observability → **B6** billing gate → **B7** native → **B8** harness seams + client/E2E correctness → **B9** docs →
> **B10** enforcement close-out. Human decisions (PHASE5_GATE §4) are attached where they bite; the plan assumes the
> recommended default. Git discipline: one branch/PR per batch (or per keystone group), base `develop`, never `main`,
> confirm before push, both forges reconciled. Verify commands run from the repo root.
>
> Finding IDs are stable; the v3 pattern applies: **for every regressed/mis-marked prior fix (T35/T36) the
> remediation adds a standing gate** so it cannot regress a third time.
