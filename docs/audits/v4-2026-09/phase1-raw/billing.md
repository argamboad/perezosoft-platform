SHA: 8c8ed4a · BASE: f52be3d

## SUMMARY
Counts: Critical 0 · High 0 · Medium 2 · Low 5 · Info 3 (10 findings, BILL-1..BILL-10).

Headline: (1) The gate's economic claim — "billing off ⇒ every tenant is Free" (ADR-027, `BillingSettings`, `Program.cs` startup log, `PlanCatalogTests`) — is not what the code does: `EntitlementService.ResolvePlanKey` never consults the gate, so any tenant with a granting `Subscription` projection keeps its paid plan while the webhook that could update it is 404. (2) The admin comp write (`PUT /api/admin/tenants/{id}/subscription`) is reachable with billing off and mints exactly such a projection — an ungated billing-reachable surface the `api/billing`-prefix arch test cannot see. (3) The 3→5 seat re-tune left seven stale "3"s in QA plan / billing story / lesson 5.3 / a test comment, and the E2E suite copies the number instead of reading the catalog.

Rules proposed: R81b (gate coverage by route table, not by attribute list), R82b (a config gate has one read site), R83b (numbers quoted from the catalog are read, not copied).

## Findings

### BILL-1 · Medium · `src/Api/Services/EntitlementService.cs:24-33`, `src/Api/Program.cs:203`, `src/Api/Configuration/BillingSettings.cs:6-7`, `tests/Api.Tests/Billing/PlanCatalogTests.cs:26-27`, `docs/DECISIONS.md` ADR-027 §1
**What:** The gate is documented and logged as "billing off ⇒ every tenant is Free", but plan resolution is gate-blind. `ResolvePlanKey` is:
```csharp
if (subscription is null) return PlanKeys.Free;
var active = subscription.Status is SubscriptionStatus.Active or SubscriptionStatus.Trialing
             && (subscription.CurrentPeriodEnd is null || subscription.CurrentPeriodEnd > now);
return active ? subscription.PlanKey : PlanKeys.Free;
```
No reference to `BillingSettings` anywhere in `src/Api/Services/**` (grep: the only consumers are the convention, `FeaturesController`, `Program.cs`). `Program.cs:203` logs `"disabled (no /api/billing routes; every tenant is Free)"`. `PlanCatalogTests.cs:26-27` asserts the premise in a comment: "with billing off no tenant has a subscription projection at all, so every tenant resolves here" — which is false whenever a projection exists (BILL-2 shows one way to create one with the gate off; flipping the flag off on a deployment that already had Stripe activity is the other).
**Why it matters:** Two opposite ops consequences, neither documented: (a) the *safe* one — flipping the flag off does NOT silently downgrade a paying tenant's quotas (their projection still resolves Pro) — so the data-safety footgun the brief asked about does not exist, but the docs say it does; (b) the *unsafe* one — with the webhook route removed (`BillingGateConvention` drops `BillingWebhookController`), a provider `canceled`/`past_due` event for that tenant is answered 404, Stripe retries for ~3 days then gives up, and the projection can never be corrected: a cancelled Pro stays Pro until `CurrentPeriodEnd` passes (a comped one — `CurrentPeriodEnd = null`, `AdminController.cs:155` — never lapses), while Stripe keeps charging (ADR-027 itself notes "switching billing off does not stop the provider charging"). Nothing logs or warns at startup that gated-off + existing provider-managed projections is an inconsistent state. The fallback is not logged either (there is no fallback to log).
**Suggested fix (one line):** Truth-up ADR-027 §1 / `BillingSettings` doc / startup log to "every tenant *without a granting projection* is Free", and add a startup warning when `!Enabled && any Subscription with StripeSubscriptionId != null` (the ops-footgun detector); leave `ResolvePlanKey` gate-blind (deliberately — a gate-aware fail-closed would be the silent-downgrade footgun).
**Gate:** `tests/Api.Tests/Billing/BillingGateTests.cs` — add "gate off, comped/pre-existing Pro projection ⇒ IEntitlementService still resolves Pro" to pin whichever behaviour is decided; a `ConfigPostureTests`-style startup-log assertion for the warning.
**Confidence:** Certain (code), Likely (Stripe retry window is external behaviour).

### BILL-2 · Medium · `src/Api/Controllers/AdminController.cs:113-165` (`SetSubscription`), `:176-203` (`RemoveSubscription`), `src/Shared.Ui/Pages/AdminConsole.razor:132-137`, `tests/Api.Tests/ArchitectureTests.cs:235-253`
**What:** The two ADR-021 enumerated billing writes live under `[Route("api/admin")]`, so `BillingGateConvention.GatedControllers` (a two-entry hard-coded set: `BillingController`, `BillingWebhookController`) never removes them, and `BillingControllers_AreAllGated` only inspects controllers whose type-level `[Route]` `StartsWith("api/billing")`. With `Billing:Enabled` unset, platform staff can still `PUT /api/admin/tenants/{id}/subscription {plan_key:"pro"}` and the console still renders the Comp/Revert buttons (`AdminConsole.razor:132,137` branch on `_detail.PlanKey`, not on the features probe). The write creates `Status = Active, CurrentPeriodEnd = null` → the tenant holds `Entitlements.ProFeature` and 10 seats.
**Why it matters:** Directly contradicts ADR-027 §1 "**Accepted consequence:** while off, nobody holds `Entitlements.ProFeature`" and `gates.md` "Consequence accepted: while off, nobody holds `Entitlements.ProFeature`". It may well be *desirable* (comp a friend during the private test without a provider) — but it is undocumented, untested, and it is the concrete path that makes BILL-1's premise false. The ADR's "The console may display the state read-only" was not implemented either (no billing-gate state anywhere in `AdminConsole.razor`; grep for `billing|features` returns only the plan badge and comp buttons).
**Suggested fix (one line):** Decide: either (a) gate the comp/revert actions too (add an `[Route("api/admin")]`-scoped action-level convention or move them to a `BillingAdminController` under `api/billing/admin` so the existing list + arch test cover them), or (b) document comp-while-off as the intended private-test mechanism in ADR-027/gates.md and hide/show the console buttons from `/api/features`.
**Gate:** `tests/Api.Tests/Billing/BillingGateTests.cs` — a `GateOff_AdminComp_*` case pinning the decision; `tests/Ui.Tests/BillingGateUiTests.cs` for the console buttons.
**Confidence:** Certain.

### BILL-4 · Low · `src/Api/Program.cs:37-41` vs `src/Infrastructure/ServiceCollectionExtensions.cs:141`
**What:** The gate is read at two independent sites with two different mechanisms: `Program.cs` binds `BillingSettings` from section `BillingSettings.SectionName` (`"Billing"`), while Infrastructure re-reads the raw string `configuration.GetValue("Billing:Enabled", false)` to decide whether the Stripe fail-fast applies. Nothing ties them together (Infrastructure cannot reference the Api-layer `BillingSettings`; there is no shared constant).
**Why it matters:** The two decisions must agree or the relaxed fail-fast (BILL-3's premise) and the route removal drift apart: a rename of `SectionName`, or a future `BillingSettings.Enabled` computed from more than one key, changes one site and not the other. `DocAndConfigSyncTests` (regex at `:54`) does catch the raw read for `.env.example` documentation, so R53's doc half is fine; the *equivalence* is unenforced.
**Suggested fix (one line):** Move `Billing:Enabled`'s key to a Core-level constant (next to `PlanKeys`) both sites read, or pass a `bool billingEnabled` into `AddInfrastructure` from the bound settings.
**Gate:** `tests/Api.Tests/Billing/BillingProviderRegistrationTests.cs` — a test that boots via `Program` (not `AddInfrastructure` directly) with the key set through the same section the convention reads.
**Confidence:** Certain (two reads), Suspected (drift).

## Candidate rules
- **R81b-cand — [machine]** — A config-gated HTTP surface is proven absent by the *route table*, not by an attribute list: with the gate bound from empty config, enumerate `EndpointDataSource` and assert no endpoint's `RoutePattern.RawText` matches the gated prefix and no endpoint's handler type lives in the gated namespace. — Enforcement: extend `ArchitectureTests.BillingControllers_AreAllGated` (or a new `GatedSurfaceTests`) over PUBAPI, HOOKS and BILLING alike; the harness already boots gate-off. — Subsumes BILL-3, informs BILL-2.
- **R82b-cand — [machine]** — A config gate has exactly one read site: the bound `*Settings` object (or a single shared key constant); no second `GetValue("<Section>:Enabled")` may exist in `src/**`. — Enforcement: `DocAndConfigSyncTests` regex over `src/` flags any raw read of a key whose section owns a `*Settings` class. — Subsumes BILL-4.
- **R83b-cand — [review→machine]** — Catalog numbers (seat/usage caps) are *read* from `PlanCatalog` wherever a test or doc asserts them; E2E tests that cannot reference Core pin them behind one named constant per project with a `PlanCatalog` cross-reference comment, and prose QA cases express seat counts relative to the cap ("cap − 1"), never as literals. — Enforcement: `DocAndConfigSyncTests` grep of `docs/**/*.md` + `tests/E2E.Tests/**` for `Free ?\(\d\)|\d of \d used|cap \d` against the catalog value. — Subsumes BILL-6, template note 2.
